# Scripts

This directory contains two command-line utilities for working with the
organization bundles under `organizations/`. Both scripts are read-only
with respect to the source markdown: they read each organization's YAML
frontmatter and write a new JSON file alongside it. Deleting a generated
JSON file and re-running the corresponding command rebuilds it from
scratch.

All commands below are run from the repository root (the directory that
contains `organizations/`), not from inside `scripts/`.

## Requirements

These scripts depend only on PyYAML, which is already declared in the
repository's root `requirements.txt`:

```
pip install -r requirements.txt
```

## `generate_org_json.py`

Each organization's bundle is spread across several markdown files
(`README.md`, `programs.md`, `population.md`, and so on), and each of
those files carries its own YAML frontmatter block at the top. This script
reads every markdown file in one organization's folder, extracts each
file's frontmatter, and writes a single JSON file that consolidates all of
it — keyed by the file's path relative to the organization folder — so the
organization's structured data can be inspected in one place instead of
across many files.

**Usage:**
```
python3 scripts/generate_org_json.py <org_folder>
```

`org_folder` is an organization's folder name under `organizations/` — just
the name, not a path. This command works identically whether run from the
repository root or from inside `scripts/`; the organization folder is
resolved relative to this script's own location, not the current
directory.


**Example:**
```
python3 scripts/generate_org_json.py synthetic-black-mountain-workforce-partnership
```

**Output:**
```
organizations/synthetic-black-mountain-workforce-partnership/synthetic-black-mountain-workforce-partnership.json
```

The output file is a JSON object whose keys are relative markdown file
paths (e.g. `"technology/inventory.md"`) and whose values are that file's
parsed frontmatter.

## `generate_mapped_json.py`

This script re-expresses an organization's frontmatter data as a JSON
document shaped for some other target schema — for example, the field
format used by [Philanthropy Data Commons](https://philanthropydatacommons.org/base-fields-list/).
The target schema is not hardcoded: the script reads a pair of
configuration files from a named folder under `scripts/mappings/`, so it
can produce differently-labeled, differently structured output for
different target schemas without any code changes.

**Usage:**
```
python3 scripts/generate_mapped_json.py <org_folder> <mapping_folder>
```

`org_folder` is an organization's folder name under `organizations/` — just
the name, not a path (e.g. `synthetic-black-mountain-workforce-partnership`).

`mapping_folder` is a folder name under `scripts/mappings/` (e.g.
`pdc`). That folder must contain exactly two files, `map.md` and
`definition.json` — described below.

This command works identically whether run from the repository root or
from inside `scripts/`; paths are resolved relative to the script's own
location, not the current directory.

**Example:**
```
python3 scripts/generate_mapped_json.py synthetic-black-mountain-workforce-partnership pdc
```

**`pdc/map.md` was generated by Claude Code for testing purposes by guessing the mapping between the frontmatter and short codes on PDC's [field list](https://philanthropydatacommons.org/base-fields-list/). The correct mapping needs to be completed by a person that understands the definition of these fields.

**Output:**
```
organizations/synthetic-black-mountain-workforce-partnership/synthetic-black-mountain-workforce-partnership_pdc.json
```

### `scripts/mappings/<mapping_folder>/map.md` — the mapping file

The mapping file specifies, for each property in an organization's
frontmatter, which field code in the target schema it corresponds to. Each
line has the form:

```
- `<markdown-file>#<property-path>`=<target-code>
```

For example:
```
- `README.md#title`=organization_name
- `README.md#description`=organization_overview
```

`<property-path>` may reach into nested YAML using `.key` for objects and
`[]` for a list of objects — `[]` expands to one mapped value per item
actually present in that file, however many there are. A line with nothing
after `=` means that property has no corresponding target code and is
skipped.

`scripts/mappings/pdc/map.md` is a worked example targeting PDC.

`scripts/mappings/mapping_empty.md` is a blank reference listing every
recognized property with no target code assigned — a starting point for
hand-building a new `map.md` in a new mapping folder.

### `scripts/mappings/<mapping_folder>/definition.json` — the JSON template file

The JSON template file specifies the exact shape of the output document.
It is a plain `.json` file containing `{{...}}` placeholders that are
filled in using the values the mapping file resolved. There is no network
access or external lookup involved — every value in the output comes from
the mapping file and the organization's own markdown.

The template must contain exactly one array holding a single object. That
object is the per-item template: the script renders one copy of it for
every mapped value, and replaces the array with the resulting list. Inside
that object, three placeholders are available:

| Placeholder    | Value                                                    |
|-----------------|------------------------------------------------------------|
| `{{code}}`   | The target code from the mapping file (e.g. `organization_name`) |
| `{{value}}`  | The value read from the organization's frontmatter        |
| `{{source}}` | `<markdown-file>#<property-path>` the value came from      |

Anywhere else in the template, `{{some_code}}` is replaced with the value
mapped to the target code `some_code` — for example, `{{organization_name}}`
inserts whichever value the mapping file assigned to that code.

A placeholder that is the entire value of a JSON string (e.g.
`"value": "{{value}}"`) is replaced with the real value as-is, preserving
its type — a list stays a list. A placeholder embedded within a longer
string (e.g. `"id-{{value}}"`) is replaced as text.

`scripts/mappings/pdc/definition.json`:
```json
{
  "changemaker": {
    "name": "{{organization_name}}"
  },
  "fields": [
    {
      "baseFieldShortCode": "{{code}}",
      "type": "string",
      "value": "{{value}}",
      "source": "{{source}}"
    }
  ]
}
```

This particular template shapes the output to resemble a PDC Application
Form field, but that is one example, not a built-in behavior — a different
mapping folder produces a differently shaped document from the same
script, with no code changes.

## Errors

| Message                                                             | Meaning                                                                                         |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `Error: ... is not a directory` / `is not a file`                   | The given path does not exist.                                                                  |
| `Error: ... is not valid JSON`                                      | The template file has a syntax error.                                                           |
| `Error: ... must contain exactly one array holding a single object` | The template is missing its per-item marker, or has more than one.                              |
| `Warning: ... not present in frontmatter, skipping`                 | Not an error — that organization does not have the referenced property, so the line is skipped. |
