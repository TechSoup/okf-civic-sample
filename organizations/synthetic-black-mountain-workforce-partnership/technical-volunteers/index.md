# Technical volunteers

**⚠ Synthetic — fabricated data.**

A bundle with two kinds of thing:

- [constraints](constraints.md) — **the org's own** rules and preferences for volunteers. The org edits this; an agent scoping a project must honor it.
- **Requests** — one file per project, each a draft the org owns and can post:
  - [cohort-outcome-reporting](cohort-outcome-reporting.md) — one participant record and three funder reports out of it, so the federal report stops being four days of one person's quarter.

**Method:** to turn this bundle into a request, an agent reads the org's [README](../../../README.md), [technology](../technology/index.md) (inventory + capability), and [constraints](constraints.md), then frames a project grounded in the org's actual gaps — and marks it a draft the org edits and blesses before anything goes out.

## Two things a scoping agent should get right here

**The problem is not that spreadsheets are bad.** A twelve-person organization tracking 190 participants a year in spreadsheets is behaving sensibly. The problem is that **three funders define a placement three ways, the state portal takes hand-keyed input, and exactly one person can assemble the result.** Any request that opens by describing the spreadsheets as the problem has misdiagnosed it and will propose a database when what's needed is a definition layer and a second person who can run the report.

**Resist the CRM.** The neighbouring bundle at [Motor City Trades](../../synthetic-motor-city-trades-institute/technology/inventory.md) shows what happens when an organization this size accepts a donated enterprise CRM: an implementation abandoned partway, a fourth system, and a website form still posting into an org nobody works in. The request below deliberately proposes something smaller than a volunteer's instinct will want to build, and says why.
