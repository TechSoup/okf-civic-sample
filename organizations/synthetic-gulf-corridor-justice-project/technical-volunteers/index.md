# Technical volunteers

**⚠ Synthetic — fabricated data.**

A bundle with two kinds of thing:

- [constraints](constraints.md) — **the org's own** rules and preferences for volunteers. The org edits this; an agent scoping a project must honor it.
- **Requests** — one file per project, each a draft the org owns and can post:
  - [archive-integrity](archive-integrity.md) — make 14,000 documents provable, so an opposing expert cannot win by questioning whether a file is the file the agency issued.

**Method:** to turn this bundle into a request, an agent reads the org's [README](../../../README.md), [technology](../technology/index.md) (inventory + capability), and [constraints](constraints.md), then frames a project grounded in the org's actual gaps — and marks it a draft the org edits and blesses before anything goes out.

## The scoping insight this bundle rewards

An agent reading this organization's technology will see a self-hosted WordPress site that was defaced in 2024 and will want to propose hardening it. That is not wrong, and Cloudflare already did most of it.

**The organization's actual exposure is that it cannot prove its own evidence.** Fourteen thousand documents cited in legal proceedings, no hashes, no provenance records, no audit trail, no immutable copy — and a defacement in its history after which it could not demonstrate that nothing else had been altered.

That is an unusual finding to reach, because **integrity problems are invisible.** Nothing is broken, nothing is down, no one has complained. The question only arrives when someone with a motive asks it, in a proceeding, at the worst possible moment. A scoping agent that gets from "website was defaced" to "the archive has no integrity story" has done the thing this collection is trying to make possible.
