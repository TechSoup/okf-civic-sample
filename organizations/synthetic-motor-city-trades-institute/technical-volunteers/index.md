# Technical volunteers

**⚠ Synthetic — fabricated data.**

A bundle with two kinds of thing:

- [constraints](constraints.md) — **the org's own** rules and preferences for volunteers. The org edits this; an agent scoping a project must honor it. **Read this one even if you skip the others** — an organization serving returning citizens has a specific and well-reasoned position on volunteer background checks, and it is not the position the rest of this collection takes.
- **Requests** — one file per project, each a draft the org owns and can post:
  - [participant-record-consolidation](participant-record-consolidation.md) — make one participant record authoritative, starting with getting conviction histories off a single unbacked-up machine.

**Method:** to turn this bundle into a request, an agent reads the org's [README](../../../README.md), [technology](../technology/index.md) (inventory + capability), and [constraints](constraints.md), then frames a project grounded in the org's actual gaps — and marks it a draft the org edits and blesses before anything goes out. An org can point its own AI at this bundle and ask, e.g., *"what would it take to answer the three-year retention question with confidence,"* and get back something like the request below.

**A note on sequencing.** The obvious project here is a consolidation, and the organization would probably ask for that. But the bundle also surfaces something more urgent: thousands of conviction histories on one desktop machine with no confirmed backup. A good scoping agent should notice that the *stated* need and the *biggest risk* are not the same thing, and say so. The request below does.
