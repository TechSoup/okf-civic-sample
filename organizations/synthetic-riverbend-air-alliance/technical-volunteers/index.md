# Technical volunteers

**⚠ Synthetic — fabricated data.**

A bundle with two kinds of thing:

- [constraints](constraints.md) — **the org's own** rules and preferences for volunteers. The org edits this; an agent scoping a project must honor it.
- **Requests** — one file per project, each a draft the org owns and can post:
  - [sensor-network-reliability](sensor-network-reliability.md) — know within an hour when a sensor stops reporting, and get seven years of readings somewhere the organization actually controls.

**Method:** to turn this bundle into a request, an agent reads the org's [README](../../../README.md), [technology](../technology/index.md) (inventory + capability), and [constraints](constraints.md), then frames a project grounded in the org's actual gaps — and marks it a draft the org edits and blesses before anything goes out. An org can point its own AI at this bundle and ask, e.g., *"what's the biggest risk to our evidence,"* and get back something like the request below.

**One note specific to this bundle.** Because the technology *is* the program here, a volunteer project is program work, not back-office work. The organization's tolerance for a volunteer breaking something is correspondingly lower, and [constraints](constraints.md) reflects that.
