# Technical volunteers

**⚠ Synthetic — fabricated data.**

A bundle with two kinds of thing:

- [constraints](constraints.md) — **the org's own** rules and preferences for volunteers. The org edits this; an agent scoping a project must honor it. For a legal-services organization these are professional-responsibility obligations, not preferences, and a volunteer cannot negotiate them.
- **Requests** — one file per project, each a draft the org owns and can post:
  - [intake-triage-assist](intake-triage-assist.md) — get field intakes into the case system in a day instead of two weeks, without building anything that gives legal advice or decides whose case is worth taking.

**Method:** to turn this bundle into a request, an agent reads the org's [README](../../../README.md), [technology](../technology/index.md) (inventory + capability), and [constraints](constraints.md), then frames a project grounded in the org's actual gaps — and marks it a draft the org edits and blesses before anything goes out.

## Why this is the collection's hardest request to scope

Someone will look at this organization and see an obvious AI opportunity. Nine hundred matters a year, intakes in three languages, a chronically oversubscribed practice, a two-week lag getting field notes into the system. There is an appealing version of this project involving a model that reads intakes, assesses them, and tells the organization which cases to take.

**That version should not be built**, for reasons that are specific and serious rather than generally cautious. The request below explains what was declined and why, then scopes the narrow thing that is genuinely useful — and notes honestly that the **highest-value half of it needs no AI at all**.

If you want one file from this collection as an example of scoping AI into a high-stakes professional context, this is it.
