# P84 — Ethnic and immigrant services

**A shared classification node.** Organizations carry this code in optional `x-civic.ntee`; the Members list below is generated from that key by `scripts/build_hubs.py`. NTEE is a US-only layer, so it reaches twelve of the fifteen.

## What this code means

**Ethnic and immigrant centers and services** — organizations whose work is oriented to immigrant, refugee, and ethnic communities. Note the oddity: **NTEE is a taxonomy of what organizations do, and this code is mostly about who they serve.**

*Title given as commonly published; confirm against the current NTEE-CC listing. **NTEE is a US IRS vocabulary** — see [index](index.md).*

## A population code inside an activity vocabulary

Three organizations carry this code and none of them does the same thing. One runs a food shelf, two are legal practices. What they share is a **population**, not an activity.

That is worth pausing on, because it is a structural feature rather than an accident:

**NTEE has no population facet.** Candid's PCS does — it separates subject codes from population codes, which is why the Chapter 510 bundle this collection was modeled on can carry `SA010500` for arts education *and* `PA010400` for adolescents as distinct edges. NTEE cannot express that, so population information gets smuggled into activity codes like this one, and the taxonomy quietly mixes two dimensions.

The practical consequence: **a query grouping by NTEE code will put a food shelf and two law offices together** and call it a category. It is a category — of served community — but nothing in the code tells a consumer that this particular code means something different from [K30](K30.md) or [I80](I80.md).

**This is the strongest argument in the collection for wanting the [PCS](../pcs/index.md) crosswalk that the collection deliberately does not have.** A vocabulary with a real population facet would put these three organizations' shared attribute where it belongs, and their activities in three different places.
