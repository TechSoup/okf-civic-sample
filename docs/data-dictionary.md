# Data dictionary — organization bundles

This is the lookup-table companion to [`civic-profile.md`](civic-profile.md) (the *why*) and [`organizations/README.md`](../organizations/README.md) (the bundle-level tour). It answers one question per row: **given a file or a field, what goes in it, is it required, and what shape does it have.**

**Legend:** **R·core** = required by OKF v0.2 core

**R·civic** = required by the `civic/0.6` profile 

## A. Files in a bundle

Every `organizations/` has the same files.

| File                                  | Record `type`           | Frontmatter?                             | Required?                 | What it holds                                                                                       |
| ------------------------------------- | ------------------------ | ----------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------- |
| `README.md`                           | `org`                   | yes — carries the R·civic fields         | **required**              | The canonical organization record: the required `x-civic` block plus prose about the organization   |
| `index.md`                            | —                       | `okf_version` only (bundle root, §8/§12) | **required**              | Plain listing of the folder — the progressive-disclosure entry point                                |
| `log.md`                              | —                       | none (reserved, §9)                      | **required**              | Edit history, date-grouped (`## YYYY-MM-DD` headings)                                               |
| `population.md`                       | `population`            | yes                                       | optional                  | Who the organization serves, in prose — where the emergent `[[wikilink]]` vocabulary lives          |
| `programs.md`                         | `programs`              | yes                                       | optional                  | What the organization runs                                                                          |
| `impact.md`                           | `impact`                | yes                                       | optional                  | Outcomes / results narrative                                                                          |
| `verification.md`                     | `verification`          | yes                                       | optional                  | A dated third-party determination — or the deliberate absence of one                                |
| `what_i_need_funding_for.md`          | `funding_need`          | yes                                       | optional                  | Funding priorities in the organization's own voice — explicitly *not* part of the published profile |
| `technology/index.md`                 | —                       | none                                       | optional                  | Listing                                                                                              |
| `technology/inventory.md`             | `technology-inventory`  | yes                                       | optional                  | What software the organization actually runs                                                        |
| `technology/capability.md`            | `technology-capability` | yes                                       | optional                  | Assessment of what it can do with that software                                                     |
| `technical-volunteers/index.md`       | —                       | none                                       | optional                  | Listing                                                                                              |
| `technical-volunteers/constraints.md` | `volunteer-constraints` | yes — `generated.by: human:org-staff`    | optional                  | **Org-authored and binding.** Anything scoping volunteer work from the bundle must honor it         |
| `technical-volunteers/<project>.md`   | `volunteer-request`     | yes                                       | optional (0–N per bundle) | One scoped volunteer project request, named for the project                                         |

## B. Record `type` values

Every frontmatter block's `type` value found in this collection, and where it appears.

| `type`                  | Appears in                            | Notes                                                                                    |
| ----------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `org`                   | bundle `README.md`                    | Primary organization record holding identity, classification, and profile metadata.      |
| `population`            | `population.md`                       | Detailed narrative describing the target communities and beneficiary populations served. |
| `programs`              | `programs.md`                         | Description of active programmatic work, initiatives, and direct services.               |
| `impact`                | `impact.md`                           | Narrative report on programmatic outcomes, statistics, and organizational results.       |
| `verification`          | `verification.md`                     | Record of official third-party audit, determination, or trust evaluation.                |
| `funding_need`          | `what_i_need_funding_for.md`          | Direct statement of current capital and funding priorities in the org's own voice.       |
| `technology-inventory`  | `technology/inventory.md`             | Inventory of software, platforms, and technical infrastructure actively in use.          |
| `technology-capability` | `technology/capability.md`            | Internal assessment of technical capacity and readiness to deploy/manage tech.           |
| `volunteer-constraints` | `technical-volunteers/constraints.md` | Binding ground rules and restrictions governing volunteer technical assistance.          |
| `volunteer-request`     | `technical-volunteers/<project>.md`   | Scoped request detailing a single technical volunteer project need.                      |
| `bundle-collection`     | `organizations/README.md`             | Metadata cataloging the collection of organization bundles as a whole.                   |
| `doc`                   | files under `docs/`                   | General documentation or technical reference file.                                       |
